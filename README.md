# وصلة — نقل مباشر بين الأجهزة

موقع ثابت يعمل على GitHub Pages، ويستخدم PeerJS Cloud العام المجاني كوسيط إشارات WebRTC. لا يحتاج صاحب الموقع إلى إنشاء حساب Cloudflare أو إعداد خادم أو إضافة نطاق.

## طريقة العمل
1. يختار المرسل الملفات وينشئ جلسة بمعرّف عشوائي.
2. ينشئ التطبيق رابطاً يحمل معرّف PeerJS ووقت انتهاء الجلسة.
3. يفتح المستقبل الرابط ويضغط «موافقة واقتران».
4. يتبادل الجهازان بيانات الاتصال عبر PeerJS Cloud، ثم تنتقل الملفات مباشرة بينهما عبر WebRTC DataConnection.
5. لا تُرسل بايتات الملفات إلى PeerJS Cloud؛ خادم PeerJS يمرر إشارات إنشاء الاتصال فقط.

## النشر
يتم نشر الملفات الثابتة بواسطة GitHub Pages من الفرع main. لا حاجة إلى Cloudflare Worker أو Durable Objects.

## حدود مهمة
- PeerJS Cloud خدمة عامة مشتركة ومجانية؛ قد تتباطأ أو تتوقف أو تُحجب في بعض الشبكات. راجع [صفحة الحالة](https://status.peerjs.com/).
- لا يوجد TURN احتياطي؛ بعض أنواع NAT أو الجدران النارية قد تمنع الاتصال المباشر.
- انتهاء الرابط يُطبّق من جهة المتصفح، وليس هناك خادم جلسات مركزي يفرضه.
- رابط الجلسة سرّ وصول عملياً؛ لا تنشره علناً. استخدم معرّفاً عشوائياً ولا تشاركه إلا مع المستقبل المقصود.
- استكمال النقل بعد إغلاق الصفحة أو انقطاع الاتصال لم يُنفذ بعد.
- لم يتم بعد إجراء اختبار نقل فعلي بين أجهزة متعددة أو اختبار أحجام كبيرة أو توافق أجهزة التلفاز.
- الملفات المستلمة تُجمع في ذاكرة المتصفح قبل تنزيلها؛ الملفات الضخمة جداً قد تستهلك ذاكرة الجهاز.
