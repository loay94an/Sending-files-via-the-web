# خطة الهندسة العكسية باستخدام REA — ملف Concepts المرفوع

## الهدف

استخدام مشروع REA الرسمي لفحص التطبيق كصندوق أسود ثابت، ثم تنفيذ وظائف مماثلة بصورة مستقلة. لا ننسخ الكود أو العلامة التجارية أو ملفات الفرش/الأصول المحمية. لا نرفع ملف APK الأصلي إلى هذا المستودع.

## مصدر العينة

- اسم الملف محلياً: `Concepts 2022.04.10.apk`
- SHA-256: `47e4e5244f2e2284349888a3fad00f407c1f0503429ec3d0e469f24924a98fdf`
- مساحة الاسم المرصودة من DEX: `com.tophatch.concepts`
- الحجم: 139,091,564 bytes
- الحالة: لم يُشغّل REA على هذه العينة في بيئة الإنشاء الحالية. الاستطلاع السابق كان ZIP/DEX/assets فقط؛ لا تعامل أسماء الفئات كإثبات لسلوك التشغيل.

## تجهيز REA على جهاز تحليل

1. استخدم Node.js بإصدار مدعوم حالياً وفق README الرسمي لـ REA: خط 22.23.4+ أو 24.22.1+ أو 26.12.1+.
2. ثبّت JDK كاملاً يتضمن `jdk.compiler`، إصدار Java 17 أو أحدث.
3. جهّز Headless JADX MCP JAR بالإصدار الذي تطلبه نسخة REA الحالية. دليل Android الحالي يذكر 0.7.1؛ تحقق من الدليل قبل التثبيت.
4. عرّف `JAVA_HOME` و`REA_JADX_MCP_JAR` بمسارات مطلقة.
5. ثبّت REA وشغّل فحص الجاهزية:

```bash
npx rea-agents setup
rea doctor --provider jadx --json
```

6. تحليل موارد Android يحتاج Apktool launcher منفصلاً يقدّمه المحلل؛ تحقق من دليل REA الحالي قبل استخدامه.
7. لا تشغّل APK غير موثوق على جهاز شخصي. تحليل JADX الثابت لا يحتاج إلى تشغيل APK أو محاكي. للفحص الديناميكي استخدم محاكي اختبار معزولاً وبموافقة صريحة.

## موجّه الوكيل المقترح بعد اتصال REA

> افحص عينة Concepts APK ذات SHA-256 المسجل أعلاه باستخدام أدوات Android التي يعلنها خادم REA. ابدأ ببيان الحزمة والتوقيع والمكونات والصلاحيات والأنشطة، ثم جرد DEX والحزم والفئات، ثم حلّل مراجع وحدات Canvas والرسم والفرش والطبقات واللمس والاستيراد والتصدير. أرجع أدلة محددة (المسار/الفئة/الطريقة/الموضع) لكل استنتاج، وافصل المشاهدات الثابتة عن الافتراضات. لا تدّع معرفة سلوك لا تثبته الأدلة. قارن النتائج بكود MafahimCanvas، واكتب قائمة فجوات مرتبة، ثم اقترح اختبارات قابلة للتنفيذ للميزات الأعلى أولوية.
